# Quarry frontend

React with Blueprint, Tailwind, TanStack Router, TanStack Query, Zustand, and Immer.
Follow the repository's [code-writing guidelines](../../AGENTS.md).

## Running locally

From the repository root:

```bash
npm install
npm run dev:frontend
```

Open `http://localhost:5173`. The login screen renders independently; signing in
and using the workspace require the API, GoTrue, and infrastructure. Sync execution
also needs the workers. The root `npm run dev` runs all four application processes.

Copy the root `.env.example` to `.env`, configure `QUARRY_BOOTSTRAP_ADMIN_EMAIL`
and the encryption key, start Docker, and run `npm run infra` before starting the
whole application. Use **Create an account** on the login screen with the configured
bootstrap email to initialize the first administrator.

The first ingestion flow is:

1. Create a project.
2. Open Keychain and create a PostgreSQL credential in that project.
3. Open the project and connect a source using that credential.
4. Test the connection or explore its tables.
5. Create a sync, choose an output location, and optionally provide a cron schedule.
6. Run the sync and inspect its automatically refreshed run history.
7. Open the output dataset to see its schema, files, and previous versions.

The dataset screen inspects catalog metadata. It does not query or preview rows
from Parquet; the backend does not expose that capability yet.

## Structure

- `src/main.tsx`: auth initialization, bootstrap states, and the router provider.
- `src/routes/`: public login and protected workspace routes.
- `src/routeTree.gen.ts`: generated by the TanStack Router plugin; do not edit.
- `src/SDKs/`: feature stores, action factories, selectors, query definitions, and UI.
- `src/components/`: shared Blueprint-based components and schema field rendering.
- `../standard-ui/`: shared `@quarry/standard-ui` workspace package, consumed by the playground.
- `src/styles.css`: Blueprint styles and Tailwind utilities, without Tailwind's
  Preflight reset so Blueprint retains its component defaults.

Components use `SDK.useWith` and handle the returned query statuses locally.
Feature stores hold domain state; QuerySDK owns the shared QueryClient. Auth checks
run before protected route loaders, with separate denied and unreachable states.

## Checks and builds

```bash
npm run typecheck --workspace=packages/frontend
npm run build --workspace=packages/frontend
```

The production bundle is written to `packages/frontend/dist`. To inspect that
bundle locally, use `npm run preview --workspace=packages/frontend`. Preview uses
the same API/authentication proxies as development.

For deployment, serve `dist` with an SPA fallback to `index.html`. Proxy `/api` to
the Quarry API and `/auth-api` to GoTrue, removing the `/auth-api` prefix. The
`/auth` path belongs to the frontend router. Alternatively, set `VITE_API_URL` and
`VITE_AUTH_URL` at build time to public service URLs and configure their allowed
origins. Never expose internal worker tokens or encryption keys through Vite
environment variables.

The existing server/worker Docker image does not serve the frontend bundle.
